## Governing acceptance rule

A finding closes only when its concrete failure mechanism is removed by source reasoning and the focused check for the changed contract passes. A green test alone is insufficient. After each batch, review its complete diff against this plan and check that earlier contracts remain intact. Do not run the full suite after every batch; reserve one canonical regression run for final qualification. Every launched test or helper process must have bounded supervision and verified process-tree cleanup.

If a later batch requires changing an earlier contract, first document the dependency and revise only that bounded contract before continuing. Stop a dependent batch when evidence contradicts the design or the required cleanup cannot be verified. Do not add unrelated features, architecture splits, graphics experiments or new release scope.

### R3 — Supported native reset — Complete; N05 remains Open

- Added one `NativeCallbackAdmission` member to the existing `RuntimeState`. Its atomic closed-bit/active-count state prevents the check-then-increment race: a callback either acquires a counted lease before closure or is rejected. The callback path takes no mutex and allocates nothing. Reset closes admission, signals workers, and waits up to 5 s for admitted calls before joining workers or resetting hook/state ownership.
- A reset invoked from an admitted callback returns without self-waiting and retains hook resources; a drain timeout likewise leaves the gate closed and retains hooks for a later control-thread retry. Successful drain is followed by the existing worker join and `CameraCorrectionGate` serialization before resource/state reset. Loader-lock detach only closes admission/signals workers; it does not wait or tear down.
- `SafeMidHookEntry` now admits all production native camera callback adapters. Gameplay/Cinematic/Dialogue correction callbacks recheck stopping and their feature gate after acquiring `CameraCorrectionGate`. Runtime settings/readback operations participate in the same admission window so reset cannot clear shared state while one is in flight; semantic readback rechecks readiness after lock acquisition.
- Preserved the replaced cinematic aspect-store contract: when admission is closed or its feature gate is inactive, the hook writes the native 16:9 value and advances RIP by the exact 10-byte instruction length. This avoids skipping the replaced native store while the remaining hooks are draining.
- Added `evidence-native-callback-reset-drain`: a deterministic callback pauses after admission but before the correction gate; concurrent reset closes readiness and waits; resumption observes stopping and cannot mutate/publish; new callbacks are rejected. The same case checks callback-originated reset returns with admission closed, a later control-thread reset drains, and closed-gate cinematic store pass-through preserves native value and continuation.
- Focused validation: new scenario PASS with Diagnostics OFF and ON; production ASI target and actual-adapter harness compiled/linked; full process-containment contract passed including explicit allowed compiler-helper cleanup; registry audit passed at 59 targets / 59 harnesses / 62 runner invocations / 104 native scenarios / 208 child executions / 3 resource targets / zero missing inputs. ### R8 — Resident continuation budget — Complete

- Replaced per-install heap allocation with one owner-thread-only fixed pool of 64 `InputWindowBinding` records. A binding is reusable only before it has been published to a window procedure; successful records are never freed or reused, preserving callback, `WM_NCDESTROY`, stale-command and foreign-subclass continuation addresses for process lifetime.
- Every allocation path is explicit: failures before publication release the reservation; after the subclass is installed, the record is permanently committed. On budget exhaustion, installation is refused, a single diagnostic is recorded, and the existing terminal/fail-open path is requested. This avoids unbounded process-lifetime growth without unsafe reclamation; the bounded memory cost is 64 records.
- Added `StableRecordPool` and focused tests for reservation reuse before publication, permanent retention after commit, exhaustion, and 64 stable records. Existing real Win32 lifecycle scenarios continue to cover native continuation, stale generations, foreign subclass chains, `WM_NCDESTROY` visibility/removal, and active-callback drain.
- Focused `input_state_harness` PASS with verified process cleanup; production ASI target compiled/linked with the pool integration; registry audit PASS (59 targets/harnesses, 62 invocations, 104 native cases / 208 children, 3 resource targets, zero missing inputs). Runs were serial, bounded and cleanup-verified; no full canonical suite or game was run.
- Repeated successful rebinds are bounded at 64 per process lifetime. If that unusual cap is reached, Overlay input/owner operation terminates safely rather than reclaiming a possibly live native continuation. No immediate reclamation, general callback redesign, or dynamic-unload guarantee was added.
